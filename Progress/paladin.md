### 队伍块算法

```
队伍块索引 = group.start + (队友序号 - 1) * group.num + 字段偏移
```

`start=57`、`num=5` 时：队友 1 = 58~62，队友 30 = 202~207。

字段偏移（`Arasaka/config.yml` 的 `group` 段）：

| 偏移 | 字段 | 说明 |
|------|------|------|
| 1 | 生命值 | % |
| 2 | 职责 | 1 坦克 2 治疗 3 输出 0 不计 |
| 3 | 驱散 | 需要驱散的类型（见下） |
| 4 | 圣光守望 | 剩余秒 |
| 5 | 圣光誓约 | 剩余秒 |

> 后两个是用户自己加的机制（1310909 / 1328548 两个光环 ID）。

### `目标类型` 的三段编码

`main.lua` 的 `getTargetDispelType` 不是 0/1/2/3，而是三段区间：

| 区间 | 含义 |
|------|------|
| `0` | 无目标 / 超出射程 / 目标已死（`updateTargetValid` 只在 `inRange and not isDead` 时才算） |
| `1~10` | 敌对：`1` = 身上没有可驱散光环，`2~10` = 有（颜色曲线细分） |
| `11~20` | 友善：`11` = 没有可驱散光环，`12~20` = 有 |

决策层用 `1 <= 目标类型 <= 10` 判敌。**早期写成 `== 1`** 会让「带可驱散 buff 的敌人」
被当成非敌人 → 防护/惩戒整条战斗链都不走。

## 二、驱散

### 驱散开关（Lua + Python 双层）

- **Lua**：`SwitchDispel()` 切换 0/1，写入像素块 + SavedVariables
- **Python**：关闭时临时移除 group 中驱散字段 → 原始逻辑跳过队友驱散 → 恢复字段
- 目标驱散不受影响（依赖 `目标类型`，不依赖 group）

### 驱散能力表（`main.lua` 的 `dispelAbilities`）

**这是驱散能否工作的总开关** —— 曲线点位完全由「能力表里的法术是否已学会」决定：

| 类型 | 驱什么 | 无限服圣骑士的法术 | 点位 |
|------|--------|-------------------|------|
| 1 | 魔法 | `4987` 清洁术 | 1/255 |
| 2 | 诅咒 | **无**（经典圣骑士没有驱诅咒的法术） | 0（写 11/255 基线） |
| 3 | 疾病 | `1152` 纯净术 / `4987` 清洁术 | 3/255 |
| 4 | 中毒 | `1152` 纯净术 / `4987` 清洁术 | 4/255 |
| 11 | 流血 | 无 | 0 |

> ⚠️ **必须写经典 ID**。正式服 ID（213634 / 213644 / 365585…）在无限服一个都不存在。
> 写错的后果：`hasLearnedAnySpell` 全 false → 曲线点位被写成 0 → 队友的「驱散」像素恒为 0
> → Python 永远匹配不到人 → **驱散永不触发**（且不报错，很难查）。
>
> 改完用 `/cy dispelprobe` 验证：类型 1/3/4 的点位应非 0，类型 2 应显示「检测不到」。
>
> ⚠️ **战斗中光环数据会受限（secret）** —— 无限服 = Decursive 里的 `DC.FOREVER`。
> 战斗 / 首领战中 `GetAuraDispelTypeColor` 返回黑色，减益类型读不到，
> Lua 写不进那一格 → 决策层找不到人 → **战斗中不驱散**。
>
> **解法：还是画进色条，只是「画」这一步改由引擎代劳** —— 把色条上「驱散」那一格
> 的纹理交给引擎（`ab:AddDispelTypeTexture`），**引擎按光环类型给它染色**
> （Decursive 受限时的正统做法）。最终像素和正式服逐字节一致
> （红0、绿=索引、蓝=类型），**Python 侧一行都不用改**。
> 所以战斗中拿到的是**精确类型**，不是盲驱。机制详见 README「十六点五、驱散机制」。
>
> 另外两点：
> - **驱散技能必须走 `dynamicSpells`**（`class/Paladin.lua` 的「清洁术」已在里面）。
>   放 `staticSpells` 的话 keymap 里只有 `unit: 0`，`get_hotkey(队友槽位, "清洁术")` 查不到 → 不驱散。
> - 原来只取 `auraInstanceIDs[1]`（第一个 debuff），第一个减益可能正好驱不掉 → 整条链断掉。
>   现在遍历所有光环找第一个能驱的。

**法术效果实测**（`wow-forever.gg` 查证）：

| spellID | 名称 | 等级 | 实测效果 |
|---------|------|------|---------|
| `4987` | 清洁术 Cleanse | 42 | 驱**中毒 + 疾病 + 魔法**（无诅咒） |
| `1152` | 纯净术 Purify | 8 | 驱**疾病 + 中毒**（无魔法） |

### 目标侧的类型映射

| 目标类型 | 含义 | 经典圣骑士能驱？ |
|---------|------|-----------------|
| 11 | 友善目标，无可驱散减益 | — |
| 12 | 魔法 | ✓（清洁术） |
| 13 | 诅咒 | ✗（经典无此能力） |
| 14 | 疾病 | ✓（清洁术 / 纯净术） |
| 15 | 中毒 | ✓（清洁术 / 纯净术） |

> Python 侧的判断集是 `(12, 14, 15)` —— **14（疾病）不能漏**，
> 早期写成 `(12, 13, 15)` 会漏掉疾病，而 13（诅咒）在经典服根本不可达。
>
> ⚠️ **目标侧**在战斗中受限时会退回**基线 11**（目标的减益类型读不到，
> 这条只影响驱邪术 / 神圣愤怒这类「按敌人减益类型选技能」的判断）。
> **队友侧**不受影响 —— 队友的「驱散」格由引擎染色，类型是精确的。

### 生物类型（驱邪术 / 神圣愤怒）—— 读不到

`UnitCreatureType` API **存在**，但值在地图限制下是 secret 值，**不能做 `==3` / `==6` 判断**。

证据：
- 客户端自带 `SpellActivationOverlay/classes/paladin.lua` 就是 `select(2, UnitCreatureType("target"))`
  + `canaccessvalue` 兜底；
- `Hekili/Game/API/Facade.lua` 的实测记录标注
  `UnitCreatureType: plain in combat; secret under the Map restriction`。

所以「神圣愤怒（亡灵/恶魔）」和「驱邪术（亡灵/恶魔）」两个分支**已从决策层撤掉**
（技能块 34/37 保留，像素继续写、CD 继续读，加回来只需改 elif）。
代价只是白费一个 GCD + 对普通怪红字报错，不会死循环。

## 三、专精判定

三层，从可靠到不可靠依次降级。

### 第一层：traitNode 探针（最可靠）

数据来自 ForeverDB `Talents.lua`：圣骑士三个专精各有一个**独有**天赋，
都要 10 点前置，同一套天赋不可能同时点亮：

| 专精 | 天赋 | traitNode |
|------|------|-----------|
| 神圣 | Divine Favor（神恩术） | 105325 |
| 防护 | Templar's Bulwark（圣殿骑士壁垒） | 105625 |
| 惩戒 | Seal of Command（命令圣印） | 105696 |

`C_Traits.GetNodeInfo(cfg, node).activeRank > 0` 命中哪一个就是哪一系。
10 级以下三个都没点，退回第二层。

### 第二层：招牌技能探测

traitNode 探针要求该系天赋有 10 点前置且已点出；没点出时退到「招牌技能」探测。
三个招牌技能各锁一系，互斥来自**专精锁**（不是正式服那种点数上限互斥）：

| 专精 | 招牌技能 | 无限服形态 | 可靠度 |
|------|---------|-----------|--------|
| 神圣 | 神圣震击（Holy Shock 1311606） | **天赋** Lv30 | 要点了天赋才进法术书 |
| 防护 | 神圣之盾（Holy Shield 20927） | 训练师技能 Lv40 | 可靠 |
| 惩戒 | 忏悔（Repentance 9623） | **天赋** | 要点了天赋才进法术书 |

`/cy spec` 的「专属技能探测」会带状态，三种取值：

- `已学会` → 查到 ID，专精直接定死
- `未学会(训练师表 N 级 ID=…)` → 名字对得上，但这个号没学（等级不够 / 专精不对）
- `训练师表里没有(天赋未解锁或名字对不上)` → **天赋技能**（神圣震击、忏悔）走这一档：
  没点天赋就没有，**不代表专精判错**

> ⚠️ 神圣震击和忏悔都是天赋，**没点对应天赋的号，技能探测也会失效**，
> 专精判定会继续退到第三层（已知不可靠）。

### 第三层：treeIDs 顺序（不可靠）

`C_Traits.GetTreeInfo` 在无限服**拿不到天赋树中文名**（`树[1] id=1100 name=nil`），
所以「按树名归类」这条路是废的，只能退到 treeIDs 顺序。

**已知问题**：实测会把防护的点数堆到第 1 位（`按 treeIDs 顺序归类: 33 0 0`，
而实际是防护专精）。

**已知 treeID**：1100 = 防护（用户实测）。另外两个未知。
补齐 treeID→专精 映射后可以**直接按树判定专精，完全不依赖天赋**（比三层探针都稳）。
需要 ForeverDB 的 `Talents.lua`（build 1.60.1.70862）来解析。

> 60 级有 33 点必然命中 traitNode，第一层够用。

## 四、圣印机制

### 七种圣印

| 编号 | 圣印 | 编号 | 圣印 |
|------|------|------|------|
| 1 | 正义 Seal of Justice | 5 | 智慧 Seal of Wisdom |
| 2 | 命令 Seal of Command | 6 | 愤怒 Seal of Wrath |
| 3 | 十字军 Seal of the Crusader | 7 | 公正 Seal of Justice (Righteous) |
| 4 | 光明 Seal of Light | | |

18 号像素给决策层「当前挂的是哪个」，208 号给「还剩几秒」。

### 计时（core/auras.lua）

圣印的 30 秒持续时间交给光环系统推算，不再自己维护锁：

| 层 | 手段 | 适用 |
|----|------|------|
| 1 | 按 **buff 名**匹配 `scanAuras("player","HELPFUL",40)` | 战斗外，最准 |
| 2 | 按 **spellID** 复查 `C_UnitAuras.GetPlayerAuraBySpellID(id)` | 多一层保险（实测战斗中它也读不到） |
| 3 | **施放计时**：`CyberDeck.Auras["圣印"]` 的 `expirationTime` | 战斗中唯一可用的手段 |

实现：

```lua
-- core/auras.lua 的 auras[2]
["圣印"] = { remaining = 0, duration = 30, expirationTime = nil, sealValue = 0 },

-- core/forever.lua 的 MarkForeverAuraCast（施放成功时）
local aura = CyberDeck.Auras["圣印"]
aura.sealValue = seal.value                    -- 1 正义 … 6 愤怒 7 公正
aura.expirationTime = GetTime() + aura.duration
```

不挂 `addAuras`：7 种圣印跨 rank 共约 30 个 spellID，列全不划算；
`MarkForeverAuraCast` 本来就能把 spellID 解析成中文名再匹配 `SEAL_ORDER`，直接写更省。

**为什么不用自维护的 `lastSealUntil`**：它在战斗外每次扫描到圣印都被改成 `now+2`，
进战斗瞬间锁就失效 → 像素归 0 → 决策层以为没挂 → **每次进战斗重放一次圣印**。
施放计时只在成功施放时写入，战斗外扫描不会碰它。

边界：

- **死亡**：`PLAYER_DEAD` 里清空 `expirationTime` / `sealValue`，否则复活后误判 30 秒
- **被驱散 / 手动取消**：计时仍在，最多空窗 30 秒（概率低，不额外处理）
- **战斗中补印**：`UNIT_SPELLCAST_SUCCEEDED` 的 `spellID` 可能是 secret，
  计时建不起来；30 秒后自然归 0 再补，不会卡死
- `duration = 30` 对应愤怒圣印实测时长（提示框显示剩余秒）

### 圣印选择（按法力回差）

**防护**（`能量值` 即法力百分比）：

| 法力 | 当前挂智慧且**未到期** | 其他情况 |
|------|----------------------|----------|
| < 50% | —（立即换） | **立即**换智慧 |
| ≥ 50% | **保持不动**，等它自己到期 | 换回愤怒 |

- 低于 50% 是**立即**切，不管当前圣印还剩多久；
- 回到 50% 以上**不立即取消**，让这颗智慧把剩余时间跑完，下次到期才换回愤怒
  （中途取消等于白丢一个 GCD + 一份回蓝）。
- 剩余时间优先读 **208 号像素**（auras 计时）；读不到（战斗中 `spellID` 是 secret，
  计时建不起来）时退回本地估算：`SEAL_DURATION(30s) - 距上次下达换智慧的时间`。

候选顺序（取第一个已学会的）：`<50%` 智慧→愤怒→正义；`≥50%` 愤怒→正义→智慧。
探测像素 50~56 表示是否学会（0 = 会 / 255 = 不会），智慧没学会时自动退到下一个候选，
不会空按。

**神圣**（< 35% 智慧）与**惩戒**（< 25% 智慧）是单点阈值。

### 补印只看编号

圣印施放成功后由插件记 30 秒（`core/auras.lua` 的 `expirationTime`），到期后
`UpdateForeverAuras` 自动把 18 号编号归 `0`。所以决策层补印的判据就一条：

```
当前圣印编号 != 想要圣印编号  →  补（2 秒防抖，只盖像素刷新的那一两个 tick）
```

| 编号 | 剩余 | 决策 |
|---|---|---|
| 6（愤怒） | 20s | 不动 |
| 6（愤怒） | 0s | 不动（编号还在，等它归 0） |
| **0** | 0s | **补**（到期了） |
| 6（愤怒），法力 40 | 20s | 换智慧 |

208 号「圣印剩余」只参与一件事：**挂智慧回蓝时判断这颗智慧有没有到期**
（未到期就保持，别中途取消）。补印不读它，避免刚按完像素还没刷新时被误判成到期。

## 五、决策层（`Arasaka/class/paladin_logic.py`）

### 三系优先级

| 专精 | 优先级 |
|------|--------|
| 神圣 | 保命(圣盾<15%→圣疗) → 清洁术驱散 → **圣光守望震击**（队友身上有 1310909 时优先给他震击）→ **圣光誓约**（坦克没 buff 就补）→ 圣光术(<60%) → 圣光闪现(≤90%) → 神圣震击(<95%) → 智慧圣印（进攻块首位）→ 审判 → 神圣打击 |
| 防护 | 圣疗自救(<10%) → 补正义之怒 → **战斗且有敌人时**：换圣印 → 补神圣之盾（只看 CD）→ 审判 → **奉献(5码内 ≥2)** → 神圣打击(5码) → 兜底起手；**战斗中暂无敌人**（目标刚死、未脱战）：仍补圣印；**脱战：什么都不做** |

### 兜底起手（`/startattack`）

`specialSpells` 里放的是**完整宏体**（不拼 `/cast`），与 `staticSpells` 同位置时优先：

```lua
specialSpells = {
    [35] = "/startattack [harm,nodead]",
},
```

- `/startattack` **不占 GCD**，可以随时按；
- `[harm,nodead]` 保证对友方/尸体不执行，不产生「无效目标」红字；
- 热键 `ALT-SHIFT-/`（第 185 个宏位）；
- `gen_paladin_keymap.py` 读取 `specialSpells`，名字由宏命令推导
  （`startattack` → `开始攻击`，见 `SPECIAL_ALIAS`）。

决策层用的是**兜底**位置，不是第一优先级：

```python
# 防护/惩戒战斗分支的**最后一个** elif
elif 自动攻击 == 0 and _upkeep_ok("开始攻击", 2):
    current_step = "开始攻击"
```

**为什么必须放最后**：`自动攻击` 像素在 `/reload` 后、停手、切目标、目标死亡时都是 0。
放在分支最前面会把后面所有 `elif`（补盾/圣印/审判…）全部挡死，表现为「一个技能都不放」。
放末尾 + 2 秒节流后，最坏情况只是每 2 秒多按一次 `startattack`，任何技能都不会被抢占。

`Arasaka/keymap/paladin.yml` 由 `Arasaka/other/gen_paladin_keymap.py` 从

- 动态技能 **7 个**（圣光术 / 圣光闪现 / 神圣震击 / 清洁术 / 圣疗术 / 圣光誓约 / **圣光守望**）× 30 = **210** 个宏位，`unit 1-30`；
- 静态技能 **33 个**（含 `[@mouseover]清洁术`）+ 1 个完整宏体 `/startattack`（静态槽 33），`unit 0`；
- 合计 **244** 个宏位（7×30 + 34），`macroKind` 上限 273；

## 七、离线技能表

`core/forever_data.lua` 的 `PALADIN` = **140 条** `{学习等级, spellID}` 训练师技能（1–60 级）。

- 生成：`python Arasaka/other/gen_forever_spells.py`（自动拉 ForeverDB manifest 并校验 sha256）
- 中文名不写死：运行时 `C_Spell.GetSpellInfo(spellID).name` 取，自动跟随客户端语言
- 作用：同一技能多个 rank 时，**按等级从高到低**找第一个 `IsSpellKnown` 的，比扫法术书的「后写覆盖」准
- 天赋技能（神恩术 / 命令圣印 / 圣殿骑士壁垒 / 圣光灌注等）不在训练师表里，仍由法术书补
- `神圣之盾`（Holy Shield 20927，**防护训练师技能 Lv40**）在训练师表里；
  `神圣震击`（Holy Shock 1311606，**神圣天赋 Lv30**）和 `忏悔`（Repentance 9623，**惩戒天赋**）
  是天赋，不在训练师表 —— 天赋没点就不会出现在法术书里
- 来源署名：**Data from ForeverDB.net**（GPL-3.0 section 7(b)，勿删文件头注释）

**离线表只是补充，不是真相**。唯一价值是「等级 → rank」的映射（运行时扫法术书拿不到），
「学没学到」永远以 `C_SpellBook.IsSpellKnown(spellID)` 为准。

**离线表会落后于客户端**：服务器每次热修都会改客户端文件。
生成脚本会自动从 `Meta.lua` 读当前 build 号写进文件头，并与本地 `Wow.exe` 版本对比告警。

查询单个法术：

```bash
python Arasaka/other/query_forever.py 4987
```
